# 台股分析 Agent：從任務圖卡到可驗收報告

想讓 AI 協助查股票，第一步是把任務說清楚。這張 VAC 將工作拆成八步，讓使用者知道要提供什麼，也讓 Agent 知道如何查詢、計算與交付。你可以把它想成一張操作清單：先確認股票，再檢查資料，最後才解釋結果。

使用前，先下載完整的 ai-stock-skill 專案，以該資料夾作為 Codex 工作目錄。請 Codex 閱讀 README 與 Skill，依說明建立隔離環境、安裝依賴，確認技能路徑及執行程式。本教材 Repo 放的是任務規格與使用方式；真正執行查詢的程式維護在第一個 Repo。

接著上傳 VAC，輸入：「使用 ai-stock-skill，查台積電 2330，列出行情、均線、資料時間與分析依據。」若要比較，可輸入：「比較台積電 2330、聯發科 2454。」指定歷史日期時，請清楚寫出年月日，並要求以單一日期參數執行。名稱與代號衝突時，先確認，不替你猜答案。

第一步「任務理解」確認代號、日期、市場及比較需求。第二步「行情取得」連接指定的 TWSE MCP，並取得官方日行情。盤中快照與完整日資料會分開呈現，報價時間也會保留。讀報告時，先問一句：這是何時的資料？不能把昨天的收盤當成此刻的成交價。

第三步「資料驗證」檢查缺值、過期、日期與價格範圍。缺少成交價時，不拿買價或賣價代替，也不補零。第四步「指標計算」交由程式計算漲跌幅、振幅及均線。量比採官方完整日成交股數，比較當日與前一交易日，不拿盤中累計量和全天成交量混算。

第五步「價量分析」使用 ai-stock-skill 0.1.0，解讀均線與比較市場表現強弱，依據價量與均線說明判讀理由。看到價格高於均線，只能先描述技術位置，不能直接推成明天一定上漲。第六步「綜合判讀」把事實、推論與資料限制分開；股票和大盤必須是同交易日，才能比較相對表現。

第七步「結果解釋」交付可閱讀報告、結構化資料與來源紀錄。你要能回答三件事：數字從哪裡來？代表哪個時間？結論根據什麼？第八步「QA 交付」再核對代號、時間與計算，並區分真實 API、模擬測試及未完成項目。有錯先修正，資料不足就清楚說明。

實際閱讀報告時，先看狀態，再看數字。部分資料可用，不代表所有欄位完整；資料過期時，也不宜描述目前強弱。若查詢遇到休市，應以來源最近提供的交易日呈現，不能單靠星期推定開盤。遇到連線失敗，先保留錯誤與來源，再決定是否重試，避免重複查詢卻沒有留下可追溯紀錄。每次操作都應使用新的輸出目錄，讓不同日期的報告分開保存，方便課堂討論與後續覆核。

本次地端回報顯示，隔離環境、依賴安裝、Skill 啟用、單股與雙股查詢、錯誤代號，以及十九項模擬測試均通過。發布檔案雜湊曾因 README 更新而失配，仍需核對修正後檔案；文件修改後必須重新建立清單，再驗證封裝內容，不能只沿用舊的 PASS。

公開教學可先示範單股，再讓學員比較兩檔，最後練習錯誤代號。企業可借此建立內部研究的資料覆核習慣，但其他管理任務仍需另設規則。現階段完成的是地端流程；盤中持續更新、雲端與 LINE 串接仍待驗證。警語：過去績效不代表未來績效。
